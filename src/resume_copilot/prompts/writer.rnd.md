# 岗位变体：研发 / 技术类（`role_family = rnd`）

适用：后端 / 前端 / 客户端 / 算法 / AI 应用 / Agent 开发 / 测试开发 / 基础架构。

## 一、模块顺序

1. **教育背景**（2 行内）— 学校、专业、排名（前 30% 才写）、核心课程只留 3–5 门岗位相关的
2. **专业技能**（3–4 条）— 语言 / 框架 / 工程化 / 基础功底，**只分「了解」与「熟悉」两层，删掉"精通"**
3. **项目经历**（2–3 个）— 技术面试的主战场，占全篇 **50–60%**
4. **实习经历** — 没有就整段删掉，不要留空标题
5. **荣誉奖项** — 一行内解决

## 二、技术面试官初筛的四个问题

1. 技术栈和 JD 匹配吗？
2. 项目里有**真实的工程约束**吗（部署 / 并发 / 失败重试 / 监控）？
3. 能不能讲清**选型理由与踩过的坑**？
4. 指标能不能被追问（基数、口径、怎么测的）？

所以项目要点必须落在「我怎么做的 + 结果怎么量的」，而不是「这个技术很厉害」。

## 三、项目要点的三种写法

- **问题—方案—结果**：
  `RAG 全链路：完成知识库清洗 → 文本分片 → 向量检索 → 检索增强，封装 HTTP 接口供业务调用，覆盖 80% 常见咨询。`
- **技术选型 + 取舍**（最能加分）：
  `分片按标题层级切分（而非定长），召回率从 __ 提到 __；代价是预处理耗时增加 __。`
- **工程化**：
  `统一 RESTful 接口规范完成模块集成与联调，Git 全流程管控，输出部署文档。`

## 四、量化的口径（别写成假的）

- 可以写：接口 QPS / P95 延迟 / 覆盖率 / 命中率 / 下载量 / Star / 用户数 / 白屏时间 / 构建时长。
- **不要写代码行数**（不可考证，只会抬高追问预期）。
- 每个指标最好带上"怎么测的"：`（180 条自建评测集，人工标注）`。
- 没有实测数据时，宁可写体量（"3 个模块""2 周交付"），也不要编一个漂亮的百分比。

## 五、语言风格

- 用工程侧动词：`实现 / 重构 / 定位 / 压测 / 联调 / 部署 / 降级 / 兜底`。
- 技术栈键名保留原文（`Spring Boot`、`RAG`、`MCP`、`GitHub Actions`），不要翻译成中文。
- 允许出现"我独立完成 / 我主导 / 我参与"，把贡献边界写清楚比写得漂亮重要。

## 六、配比与禁忌

- 项目占 50–60%，技能 20%，教育与荣誉 20%。
- 禁忌：技能堆名词却说不出一处细节；把课程作业写成"系统"；写"精通 XX"；把培训班同款项目（秒杀、外卖、博客）当主项目——若确实做过，**必须写清你额外解决了什么**（限流策略？幂等？对账？）。
- 2026 年的加分项：AI 工具链的**把关能力**（验收标准、回归用例、Review 规则），而不是"我会用 Cursor"。

## 七、自检

- [ ] 每个项目能否用一句话说清"难在哪、你怎么解决的"？
- [ ] 有没有至少一个指标带口径？
- [ ] 技能栏里每一条，面试官追问三层你答得上来吗？答不上来的删掉。
