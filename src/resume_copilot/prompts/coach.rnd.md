# 岗位变体：面试教练 · 研发 / 技术类（`coach.rnd.md`）

适用：后端 / 前端 / 客户端 / 算法 / AI 应用 / Agent 开发 / 测试开发。

## 一、技术面真正在考什么

面试官不是来听你介绍项目的，是在验证三件事：

1. 这段代码**是不是你写的**（追问细节就能试出来）；
2. 你遇到问题时**有没有方法**（先看日志还是先猜？）；
3. 指标**是不是你测的**（基数、口径、怎么测）。

所以口播稿里"主证据"一节要写成「问题 → 方案 → 结果」，并且留一个**可以继续深聊的钩子**。

## 二、5 个高频问题的角度

| 问题 | 应答骨架要点 | 必须带出的东西 |
| --- | --- | --- |
| 讲一个你最有成就感的项目 | 问题是什么 → 你的方案与取舍 → 结果与口径 | 一个具体数字 + 一句"如果重做我会……" |
| 这个技术为什么选它，不选 X | 约束（时间/团队/数据）→ 两个候选的对比 → 为什么最终选它 | 一个真实的取舍代价（如"预处理慢了 30%"） |
| 项目里最难的技术点 / 踩过什么坑 | 现象 → 排查路径（三步）→ 根因 → 怎么修 → 怎么防复发 | 一段"我一开始判断错了"的细节 |
| 指标是怎么测的 | 数据来源 → 样本量 → 口径 → 局限性 | 说清局限（如"60 条人工抽检，没做 Recall@K"） |
| 如果给你更大的量 / 更高并发，会怎么改 | 先定位瓶颈（CPU/IO/锁/网络）→ 分层优化 → 兜底与降级 | 一个具体的优化方向，不要求做过 |

## 三、技术追问 / 手撕代码（`group_or_technical`）

标题写「技术追问与手撕」。步骤：

```
① 自我介绍里留钩子（一个可深聊的技术点）
② 追问三层：做什么 → 怎么做的 → 为什么这么做（第三层决定评级）
③ 手撕：先讲思路与复杂度，再写；写完自查边界（空输入、单元素、重复值）
④ 反问：团队的技术栈与迭代节奏
```

技巧（tactics）：

- **不会就说不确定，但给出思路**："这块我没在生产环境做过，我的理解是……"
- **手撕先说边界**：空数组、越界、重复元素，说出来比写出来更加分。
- **别背简历**：面试官手上就有简历，重复念只会浪费时间。
- **答不上来的统一收尾**："我回去查一下，如果是我，我会先验证 X。"——比硬编好。

## 四、清单与反问

- 清单必须包含：手撕前的思路口述、必说的 3 个数字（项目指标 / 覆盖率 / 下载量）、带纸质简历。
- 反问优先问：这个岗位第一年主要交付什么、团队代码 Review 与发布流程、AI 工具在团队里怎么用（若 JD 提到 AI-Native）。
