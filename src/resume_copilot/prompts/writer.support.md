# 岗位变体：实施 / 运维 / 技术支持类（`role_family = support`）

适用：实施工程师、交付工程师、运维、技术支持、售前技术支持、驻场、客户成功。

## 一、模块顺序

1. **教育背景**（2 行内）
2. **专业技能**（3–4 条）— 系统与网络、数据库、脚本、工具链
3. **项目 / 实施经历**（2–3 段）— 主战场，占全篇 **45–55%**
4. **实习经历**
5. **荣誉与证书**（一行）

## 二、这类岗位在筛什么

面试官关心你能不能**独自把一套东西装到客户现场并让它跑起来**：

1. 会不会排障（有章法，不是靠猜）
2. 能不能和客户说话（把技术问题翻译成客户能懂的话）
3. 扛不扛得住驻场与倒班
4. 有没有留下可复用的东西（文档、脚本、巡检表、FAQ）

## 三、要点的写法

- **交付**：`独立完成 __ 套 __ 的部署与联调，覆盖 __ 台设备 / __ 个点位，按计划 __ 天内上线。`
- **排障**：`定位 __ 问题（现象 → 排查路径 → 根因），把平均恢复时间从 __ 压到 __，沉淀 __ 条巡检项。`
- **客户沟通**：`为 __ 名客户管理员做培训，输出 __ 页操作手册与 FAQ，把重复咨询量降低 __。`
- **可复用**：`编写 __ 脚本 / 巡检表，把 __ 步骤从手工改为自动，单次节省 __ 小时。`

## 四、语言风格

- 用交付侧动词：`部署 / 联调 / 巡检 / 排障 / 割接 / 培训 / 复盘 / 交接`。
- 症状与根因分开写，体现"排查有路径"，而不是"最后修好了"。
- 环境要写清（客户现场 / 内网 / 混合云），这是这类岗位的语境。

## 五、配比与禁忌

- 实施/项目占 45–55%，技能 20–25%。
- 禁忌：只写"负责维护 XX 系统"没有规模与结果；把"会用 Linux 命令"当技能；不提客户沟通（这是本岗位的核心能力之一）；不写驻场/出差意愿。
- 加分：证书（网络 / 安全 / 云厂商）、驾驶执照、能接受轮班与长期驻场——放在 `header.meta` 或荣誉行。

## 六、自检

- [ ] 有没有一段经历体现"客户现场 + 自己搞定"？
- [ ] 排障那条能不能讲出三步排查路径？
- [ ] `header.meta` 有没有写驻场/出差/轮班意愿？
