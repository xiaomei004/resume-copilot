# 岗位变体：面试教练 · 实施 / 运维 / 技术支持类（`coach.support.md`）

适用：实施工程师、交付工程师、运维、技术支持、售前技术支持、客户成功。

## 一、这类面试真正在考什么

1. **能不能一个人把东西装到客户现场并跑起来**（独立性与动手能力）；
2. **排障有没有章法**（不是碰运气）；
3. **能不能和客户好好说话**（很多事故是沟通事故）；
4. **扛不扛得住驻场 / 轮班 / 出差**（硬筛条件）。

## 二、5 个高频问题的角度

| 问题 | 应答骨架要点 | 必须带出的东西 |
| --- | --- | --- |
| 讲一次你独立交付 / 排查的经历 | 现场情况 → 你做了什么 → 结果（上线/恢复时间） | 一个客户现场的细节 |
| 客户现场出故障，客户在催，你怎么处理 | 先安抚并给时间点 → 同时分层排查（网络/应用/配置/数据）→ 定位后给规避方案 → 事后复盘 | 一条"先给时间预期"的沟通动作 |
| 客户提了一个你做不到的需求 | 接住（记录并复述）→ 说清边界与代价 → 给替代方案 → 拉内部资源 | 一次"没答应但没有丢客户"的经历 |
| 你怎么保证交付质量 | 清单化（上线前检查表）→ 变更留痕 → 回滚预案 → 文档沉淀 | 一个你写过的检查表/手册 |
| 能接受长期驻场 / 出差 / 轮班吗 | 明确表态 + 说明家庭与个人条件支持 | 一句干脆的回答，不要绕 |

## 三、客户现场处置（`group_or_technical`）

标题写「客户现场处置」。步骤：

```
① 先稳住人：复述问题、给出时间预期（"我 10 分钟内给你初步判断"）
② 分层排查：物理/网络 → 系统/服务 → 配置/版本 → 数据
③ 给方案：先规避（让客户业务先跑起来），再根除
④ 收尾：书面复盘 + 沉淀检查项，避免复发
```

技巧（tactics）：

- **不要在现场猜**：先要日志/现象，能复现再动手。
- **每次变更都留退路**：改配置前备份、改之前想好怎么回滚。
- **把技术语言翻译成客户语言**："不是设备坏了，是这条链路的时间配置对不上，业务会时断时续。"
- **不要承诺做不到的事**：可以承诺"今晚给你一个明确的原因"。

## 四、清单与反问

- 清单必须包含：驻场/出差意愿的一句话说法、必说的 3 个数字（点位数 / 恢复时间 / 客户数）、带纸质简历。
- 反问优先问：新人会不会直接独立驻场、典型客户的规模、值班与轮班制度。
